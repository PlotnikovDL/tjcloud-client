# Дополнения для TJCloud Client

## Проект и инструменты

- Канонический репозиторий: `https://github.com/PlotnikovDL/tjcloud-client`. Локальная рабочая копия: `C:/projects/1c-tools/tjcloud-client`.
- `TjClient.Core` - логика клиента, `TjClient.Wpf` - WPF-интерфейс, `TjClient.Tests` - native-тесты, `tests` - Python-тесты упаковки и политики веток.
- `scripts` - сборка и проверки, `packaging` - установщик, `.github/workflows` - CI и выпуск. Сервер в этот репозиторий не входит.
- SDK .NET закреплён в `global.json`: `10.0.302`. Не обновлять SDK, зависимости или lock-файлы попутно с другой задачей.
- Единственный источник версии приложения - `Version` в `Directory.Build.props`. Метаданные, названия пакетов и тег выводятся из него. Не добавлять отдельную версию в UI.
- Мастер установки и удаления, текст лицензии для чтения в мастере и описание каждого GitHub Release должны быть на русском. Перед выпуском проверять экраны установки, кнопки и подтверждение выхода.

## Ветки и review

- Ветка по умолчанию - `master`. Рабочие ветки `feature/*` создавать от актуального `origin/develop`, при открытии PR явно выбирать `develop` целевой веткой.
- Изменения в `develop` и `master` вносить только через PR. Маршрут: `feature/*` -> `develop` -> `master`. PR в `master` допускается только из `develop` этого же репозитория.
- Для слияния обязательны успешные проверки `policy` и `build` и разрешение всех обсуждений. Ревью второго участника добровольное.
- Не выполнять прямой push, force-push, обход защиты, самоодобрение или автоматическое слияние. Защита распространяется на администратора. Коммит, push, слияние и выпуск требуют разрешения соответствующего этапа задачи.

## Проверки и выпуск

- Быстрая проверка: `python -m unittest discover -s tests -v`. Полная сборка с native-тестами и smoke: `./scripts/Build.ps1 -ArtifactsRoot ./artifacts/build-check` с новым каталогом вывода.
- При параллельной сборке задавать отдельный `ArtifactsRoot` или `ArtifactsPath`. Не перезаписывать чужие результаты.
- `scripts/Test-BranchPolicy.ps1` проверяет маршрут PR, точное совпадение тега с центральной версией и реальное Git-происхождение коммита тега из `origin/master`. Для проверки тега нужен checkout с полной историей.
- PR CI остаётся read-only, без release-секретов. Права записи и attestation допустимы только в отдельном job выпуска после успешных проверок тега и сборки.
- `scripts/Test-Installer.ps1` запускать только на временном GitHub-hosted Windows runner. Не подделывать окружение ради установки на рабочем ПК. Не использовать настоящий профиль, ключ или журналы пользователя в тестах.
- Выпуск разрешает владелец отдельно. При согласованном выпуске сверить `Version`, SHA проверенного `origin/master` и отсутствие тега. Владелец создаёт `v<Version>` на этом коммите. Проверить SHA тега на GitHub, дождаться `Tagged release` и подтверждения окружения `release`, проверить пять опубликованных файлов и их подписи и контрольные суммы. Перемещение и удаление тегов `v*` запрещены.
- Для подачи в WinGet использовать установщик из публичного выпуска и проверенный манифест. Отправка в каталог требует отдельного разрешения владельца. Канал подписанных обновлений, portable-режим и проверка установки описаны в `docs/DISTRIBUTION.md`.
