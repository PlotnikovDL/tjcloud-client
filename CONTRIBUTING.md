# Участие в разработке

Этот репозиторий - каноническое место разработки Windows-клиента TJCloud. Сервер развивается отдельно. Не добавляйте сюда его исходники, закрытую историю, конфигурацию хостинга или данные.

- Создавайте `feature/*` от актуального `develop` и Pull Request в `develop`. Кратко опишите проблему, изменение и реальные проверки.
- Для исправления сначала добавляйте воспроизводящий тест. При изменении интерфейса проверяйте настоящее WPF-окно на синтетических данных, а не только успешность компиляции.
- Используйте SDK из `global.json`, locked restore и существующий набор тестов. Не отключайте аудит зависимостей или проверки ради зелёного результата.
- Не меняйте протокол, привязку ключа/согласий, поведение очереди или выбранный исторический период без отдельного обоснования и регрессии.
- Никогда не добавляйте настоящие журналы, ключи, профили, дампы, корпоративные имена и внутренние адреса. Используйте `example.org`, `APP01-SERVER` и явно синтетические данные.
- Тексты интерфейса и документация - на русском. Для тире используйте ASCII `-`.
- Для новых зависимостей фиксируйте версию, лицензию и lock-файлы.
- Изменение упаковки проверяйте отдельно от бизнес-логики: установка, обновление, удаление и сохранение пользовательского профиля.
- Публикация GitHub Release и отправка пакета в WinGet - отдельные действия. Подготовленный manifest не означает принятие пакета Microsoft.

## Ревью и слияние

Автор описывает изменение и результаты проверок в PR. При необходимости он может попросить второго участника о ревью. После успешных проверок и разрешения обсуждений любой участник с правом записи, включая автора, может вручную слить PR.

`master` - ветка по умолчанию и ветка подготовки выпуска. Для разработки используйте `develop` и явно выбирайте её целевой веткой PR из `feature/*`. Для обеих веток обязательны PR и успешные проверки `policy` и `build` на актуальном коммите. Требования действуют и для администратора. Прямой push, force-push, удаление защищённых веток и обход защиты запрещены.

PR в `develop` принимается только из `feature/*`. PR в `master` - только из `develop` этого же репозитория.

## Решение о выпуске

Владелец `PlotnikovDL` отдельно разрешает выпуск и создаёт тег `v<Version>`. Версия должна точно совпадать с `Directory.Build.props`, а коммит тега - входить в историю `origin/master`. Теги `v*` нельзя перемещать или удалять. Успешный CI, review или слияние сами по себе не разрешают публикацию Release или отправку в WinGet.
