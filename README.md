# TJCloud Client

<img src="TjClient.Wpf/Assets/tjcloud-client-256.png" width="96" height="96" alt="TJCloud Client: облако со стрелкой отправки">

[![Windows build](https://github.com/PlotnikovDL/tjcloud-client/actions/workflows/ci.yml/badge.svg)](https://github.com/PlotnikovDL/tjcloud-client/actions/workflows/ci.yml)

Открытый Windows-клиент доставки завершённых файлов технологического журнала 1С в совместимый сервис TJCloud. C#, WPF, .NET 10, Windows x64. Лицензия [MIT](LICENSE).

Клиент выделен в самостоятельный репозиторий: для его сборки не нужны исходники сервера. Здесь находится код клиента, тесты и инструменты упаковки, а не серверная часть сервиса.

## Статус

Ранняя версия. Для реальной отправки нужен совместимый получатель с включённым API и выданный им ключ источника. Публикация исходников клиента сама по себе не включает приём журналов на публичном сайте.

GitHub Release пока не опубликован, пакет в каталоге WinGet отсутствует. Подготовка к WinGet ведётся отдельно от включения в каталог Microsoft. [Установщик, CI, релизы и подготовка WinGet](docs/DISTRIBUTION.md).

## Как скачать

1. Войдите в учётную запись GitHub и откройте [Actions -> Windows build](https://github.com/PlotnikovDL/tjcloud-client/actions/workflows/ci.yml).
2. Выберите последний **успешный** запуск для ветки `develop`. Убедитесь, что весь запуск завершён со статусом Success, а не только отдельный шаг.
3. В разделе Artifacts скачайте `windows-packages`. Для скачивания нужен вход в GitHub. Артефакты хранятся 14 дней, поэтому старый запуск может уже не содержать доступного файла.
4. Распакуйте архив артефакта. Внутри находятся версионные установщик `*-setup.exe`, portable ZIP и `SHA256SUMS.txt`. Для portable-запуска распакуйте ZIP целиком и запустите `TjCloudClient.exe`.

Номер версии сборки CI указан в имени файла. В версии 1.0.1 экземпляру, установленному через Setup, можно разрешить проверку подписанных обновлений. Для доставки обновлений нужен опубликованный подписанный выпуск. Для ручного обновления portable-версии закройте клиент и распакуйте новый ZIP в отдельную папку. Профиль и очередь сохраняются.

## Какие данные передаются

- Пользователь выбирает локальную папку или UNC-каталог. Клиент работает с правами текущего пользователя, SMB-пароли не запрашивает.
- Принимаются только поддерживаемые завершённые `.log` в каталогах процессов. Источник должен закончить запись во временное имя и опубликовать файл атомарным переименованием. **Активная папка записи ТЖ не подходит.**
- До отправки выполняется проверка папки и получателя. Нужны два отдельных согласия: на завершённость выгрузок и на передачу указанному получателю.
- Передача идёт по HTTPS с обычной проверкой сертификата и без автоматических перенаправлений. При смене адреса старый ключ и согласие не переиспользуются.
- Клиент не меняет и не удаляет исходные журналы. Очередь и подтверждённые смещения сохраняются между запусками.
- **Содержимое журналов не обезличивается.** В них могут быть тексты запросов, имена и другие чувствительные сведения. Передавайте только разрешённые данные согласованному получателю.

Подробнее: [безопасность](SECURITY.md) и [протокол передачи](docs/PROTOCOL.md).

## Использование

1. Запустите клиент и выберите каталог завершённых выгрузок.
2. Укажите ключ источника. Адрес сервиса, интервал и начальный режим находятся в настройках.
3. Нажмите Проверить, проверьте показанного получателя и подтвердите оба согласия.
4. Нажмите Запустить. Для одного цикла выберите Ещё -> Отправить сейчас.

Новый профиль содержит `https://app.tjcloud.ru`, но открытие окна не запускает сеть или передачу. Существующие адрес, ключ и очередь не заменяются.

По умолчанию отправляются только новые пути после начала наблюдения. Исторический режим выбирается явно по дате изменения файлов. Период уже начатой очереди сохраняется. Смена папки создаёт отдельный контекст наблюдения.

Пауза останавливает отправку, Отменить прерывает проверку. Закрытие окна оставляет приложение в трее. Полный выход - через меню значка. Автозапуск выключен по умолчанию и меняется только по явному нажатию флажка.

Профиль и SQLite-очередь находятся в `%LOCALAPPDATA%/TJCloudClient`. Ключ защищён DPAPI CurrentUser. Эти файлы не предназначены для переноса между пользователями Windows. Не публикуйте профиль и не присылайте ключ в Issues.

Состояния Получено сервером, Импортируется и Импортировано различаются. Принятый файл не отправляется автоматически повторно ради повторного импорта. Ошибка доступа к исходной папке остаётся видимой.

## Самостоятельная сборка

Нужны Windows x64 и SDK, указанный в `global.json`.

```powershell
dotnet restore TjClient.slnx --locked-mode
dotnet run --project TjClient.Tests -c Release --no-restore
dotnet publish TjClient.Wpf -c Release -r win-x64 --self-contained true --no-restore -o artifacts/publish/win-x64
```

Для portable-запуска нужна **вся** папка publish, не только EXE. Приложение не требует установленного .NET runtime у пользователя. Зависимости закреплены lock-файлами. Предупреждения аудита не отключаются.

Тесты используют синтетические файлы и собственный loopback HTTPS. Тестовый CA доверяется только тестовым HTTP-обработчиком, не устанавливается в Windows. Настоящие ключи и работающий профиль пользователя для тестов не нужны. `--smoke-test` у опубликованного EXE открывает отдельное тестовое окно без сети и автозапуска, сохраняет результат рядом с приложением в `gui-smoke` и завершает процесс.

Визуальная проверка:

```powershell
dotnet run --project TjClient.Tests -c Release -- --visual-compact artifacts/screenshots
```

Это реальные WPF-контролы с синтетической очередью. Рендер при разных DPI не заменяет проверку переноса окна между мониторами.

## Доверие к сборкам

Открытый код даёт возможность проверки, но сам по себе не доказывает безопасность готового EXE. Публичный CI, точный commit/tag, контрольные суммы и подтверждение происхождения сборки связывают релиз с исходниками. Это не антивирусный сертификат. Неподписанные preview-сборки могут вызывать предупреждение SmartScreen.

## Ветки и выпуск

Разработка идёт через `feature/*` -> Pull Request в `develop` -> Pull Request из `develop` в `master` того же репозитория. Ветка по умолчанию - `develop`. Для слияния в обе основные ветки обязательны PR, успешные проверки `policy` и `build` и разрешение обсуждений. Ревью второго участника добровольное.

Слияние не означает выпуск. Решение о релизе принимает владелец отдельно. Только явно отправленный им тег `v<Version>` запускает публикацию, после проверки версии и принадлежности коммита истории `master`.
