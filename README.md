# TJCloud Client

<img src="TjClient.Wpf/Assets/tjcloud-client-256.png" width="96" height="96" alt="TJCloud Client: облако со стрелкой отправки">

[![Windows build](https://github.com/PlotnikovDL/tjcloud-client/actions/workflows/ci.yml/badge.svg)](https://github.com/PlotnikovDL/tjcloud-client/actions/workflows/ci.yml)

Открытый Windows-клиент для передачи событий технологического журнала 1С в совместимый сервис TJCloud. C#, WPF, .NET 10, Windows x64. Лицензия [MIT](LICENSE).

Клиент выделен в самостоятельный репозиторий: для его сборки не нужны исходники сервера. Здесь находится код клиента, тесты и инструменты упаковки, а не серверная часть сервиса.

## Статус

Ранняя версия. Для реальной отправки нужен совместимый получатель с включённым API и выданный им ключ источника. Публикация исходников клиента сама по себе не включает приём журналов на публичном сайте.

Публичные версии доступны в [GitHub Releases](https://github.com/PlotnikovDL/tjcloud-client/releases). Идентификатор для каталога WinGet - `TJCloud.Client`. Проверить наличие пакета в каталоге можно командой `winget search --exact --id TJCloud.Client --source winget`.

## Как скачать

Для Windows x64 скачайте [установщик 1.0.4](https://github.com/PlotnikovDL/tjcloud-client/releases/download/v1.0.4/TJCloudClient-1.0.4-win-x64-setup.exe) или [portable ZIP](https://github.com/PlotnikovDL/tjcloud-client/releases/download/v1.0.4/TJCloudClient-1.0.4-win-x64.zip). Русский мастер устанавливает клиент для всех пользователей в `C:\Program Files\TJCloudClient` на системном диске C. Windows запросит права администратора. Для запуска без установки распакуйте ZIP целиком и откройте `TjCloudClient.exe`. Проверьте скачанный файл по [контрольным суммам выпуска](https://github.com/PlotnikovDL/tjcloud-client/releases/download/v1.0.4/SHA256SUMS.txt).

При переходе с установки 1.0.1 для текущего пользователя отключите автозапуск, если он включён, завершите клиент через трей и удалите старую программу в параметрах Windows. Затем установите новую версию и при необходимости включите автозапуск. Ключ, согласия и история очереди сохраняются в профиле Windows. Остальные пользователи компьютера настраивают собственное подключение.

Для проверки сборки до публикации выпуска откройте [Windows build для master](https://github.com/PlotnikovDL/tjcloud-client/actions/workflows/ci.yml?query=branch%3Amaster), выберите успешный запуск и скачайте артефакт `windows-packages`. Для скачивания артефактов CI нужен вход в GitHub. Срок хранения - 14 дней.

Номер версии сборки CI указан в имени файла. В версии 1.0.1 экземпляру, установленному через Setup, можно разрешить проверку подписанных обновлений. Для доставки обновлений нужен опубликованный подписанный выпуск. Для ручного обновления portable-версии закройте клиент и распакуйте новый ZIP в отдельную папку. Профиль и очередь сохраняются.

## Какие данные передаются

- Пользователь выбирает локальную папку или UNC-каталог. Клиент работает с правами текущего пользователя, SMB-пароли не запрашивает.
- Клиент читает часовые файлы `.log` в каталогах процессов прямо из папки технологического журнала. 1С может продолжать запись. Если опрос застал многострочное событие в середине записи, клиент дождётся его окончания.
- До отправки выполняется проверка папки и получателя. Пользователь разрешает передачу событий из выбранной папки указанному получателю.
- Передача идёт по HTTPS с обычной проверкой сертификата и без автоматических перенаправлений. При смене адреса старый ключ и согласие не переиспользуются.
- Клиент не меняет и не удаляет исходные журналы. Очередь и подтверждённые смещения сохраняются между запусками.
- **Содержимое журналов не обезличивается.** В них могут быть тексты запросов, имена и другие чувствительные сведения. Передавайте только разрешённые данные согласованному получателю.

Подробнее о данных и их передаче см. в [политике конфиденциальности](PRIVACY.md), [описании безопасности](SECURITY.md) и [протоколе передачи](docs/PROTOCOL.md).

## Использование

1. Запустите клиент и выберите папку технологического журнала, например `C:\TehJournal`.
2. Укажите ключ источника. Адрес сервиса, интервал и начальный режим находятся в настройках.
3. Нажмите Проверить, проверьте показанного получателя и разрешите передачу событий.
4. Нажмите Запустить. Для одного цикла выберите Ещё -> Отправить сейчас.

В новом профиле указан адрес `https://app.tjcloud.ru`. Кнопка «Проверить» связывается с получателем. После подтверждения получателя можно включить наблюдение или отправить события один раз. При повторном открытии клиент возобновляет ранее включённое наблюдение. Если разрешены автообновления, установленный клиент отдельно обращается к GitHub.

По умолчанию клиент начинает с конца существующих файлов и отправляет новые события. Интервал опроса задаётся в секундах, от 60 до 86 400. При обновлении сохранённый интервал от 5 до 59 секунд увеличивается до 60. Чтобы отправить ранее пропущенные файлы из той же папки, нажмите «Пауза». В настройках выберите «Существующие с датой изменения от» и укажите первый день включительно. Нажмите «Проверить», подтвердите получателя и возобновите наблюдение. Уже принятые сервером файлы повторно не отправляются. Для другой папки ведётся отдельная очередь.

Пауза останавливает отправку, Отменить прерывает проверку. Закрытие окна оставляет приложение в трее. Полный выход - через меню значка. Автозапуск выключен по умолчанию и меняется только по явному нажатию флажка.

Профиль и SQLite-очередь находятся в `%LOCALAPPDATA%/TJCloudClient`. Ключ защищён DPAPI CurrentUser. Эти файлы не предназначены для переноса между пользователями Windows. Не публикуйте профиль и не присылайте ключ в Issues.

Состояния Получено сервером, Импортируется и Импортировано различаются. Принятый файл не отправляется автоматически повторно ради повторного импорта. Ошибка доступа к исходной папке остаётся видимой.

## Самостоятельная сборка

Нужны Windows x64 и SDK, указанный в `global.json`.

```powershell
dotnet restore TjClient.slnx --locked-mode
dotnet run --project TjClient.Tests -c Release --no-restore
dotnet publish TjClient.Wpf -c Release -r win-x64 --self-contained true --no-restore -o artifacts/publish/win-x64
```

Для portable-запуска нужна **вся** папка publish, не только EXE. Приложение не требует установленного .NET runtime у пользователя. Зависимости закреплены lock-файлами. Предупреждения аудита не отключаются.

Тесты используют синтетические файлы и локальный HTTPS-сервер. Тестовому центру сертификации доверяет только тестовый HTTP-клиент. Параметр `--smoke-test` открывает тестовое окно без сети и автозапуска, сохраняет отчёт в `%TEMP%\TJCloudClient-gui-smoke` и завершает процесс.

Визуальная проверка:

```powershell
dotnet run --project TjClient.Tests -c Release -- --visual-compact artifacts/screenshots
```

Это реальные WPF-контролы с синтетической очередью. Рендер при разных DPI не заменяет проверку переноса окна между мониторами.

## Доверие к сборкам

Проверить происхождение файлов выпуска можно по тегу, контрольным суммам и подтверждениям сборки GitHub. Клиент проверяет подпись Ed25519 при автообновлении. Установщики 1.0.1 и 1.0.2 выпущены без подписи издателя Windows (Authenticode). SmartScreen может показать предупреждение о неизвестном приложении. При проверке 1.0.2 на чистой Windows такое предупреждение остановило автоматическую установку из локального манифеста WinGet.

## Ветки и выпуск

На главной странице репозитория открывается `master`. Для разработки создайте ветку `feature/*` от `develop` и выберите `develop` целевой веткой PR. Для подготовки выпуска откройте PR из `develop` в `master` этого же репозитория. Для слияния в обе основные ветки обязательны PR, успешные проверки `policy` и `build` и разрешение обсуждений. Ревью второго участника добровольное.

Слияние не означает выпуск. Решение о релизе принимает владелец отдельно. Только явно отправленный им тег `v<Version>` запускает публикацию, после проверки версии и принадлежности коммита истории `master`.
