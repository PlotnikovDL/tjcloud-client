# Автообновление клиента 1.0.1

В версии 1.0.1 клиент предлагает подписанные автообновления, когда запущен из каталога установки Setup для текущего пользователя. Для обновления portable-копии закройте клиент и распакуйте новый ZIP. Состояние сквозной проверки конкретной сборки доступно в GitHub Actions.

## Поведение для пользователя

- Первый обычный запуск предлагает отдельно разрешить автообновления. До разрешения запросы обновлений не выполняются. Это согласие не заменяет два согласия на передачу журналов.
- Разрешение можно отозвать в настройках. Предусматривается ручная проверка обновлений.
- После разрешения клиент проверяет стабильные выпуски и может скачивать обновление в фоне. Отсутствие сети не мешает обычной работе текущей версии.
- Скачанный пакет проверяется криптографически до запуска. Проверки только SHA-256 с того же сервера недостаточно для автоматической установки.
- Установка не прерывает неподтверждённую передачу. Клиент согласованно останавливает наблюдение, завершает или отменяет текущую операцию и освобождает файлы программы до запуска установщика.
- После успешной установки клиент запускается снова. Папка, ключ, согласия, очередь и намерение продолжать ранее разрешённое наблюдение сохраняются. Обновление не должно самовольно включать ранее выключенное наблюдение.
- При ошибке проверки подписи, неполной загрузке или неподходящей версии установщик не запускается. Установка более старой версии автоматически не предлагается.
- Номер версии берётся из assembly metadata и виден в окне. Единственный источник версии проекта - `Directory.Build.props`.

## Границы реализации

Основной кандидат - стабильная версия NetSparkle, совместимая с WPF/.NET 10 и существующим Inno Setup. Точные API и поведение установки/перезапуска проверяются перед интеграцией. Самописный загрузчик с запуском непроверенного EXE не допускается.

Для обновлений используется отдельный сетевой компонент. Он не получает ключ источника, адрес получателя журналов или содержимое очереди. Пользовательские журналы по каналу обновлений не передаются.

Открытый ключ проверки можно включать в приложение. Закрытый ключ подписи не попадает в репозиторий, аргументы команд или журналы. Выпуски подписываются в защищённом release workflow. Криптографическая подпись обновления и Authenticode издателя Windows решают разные задачи; настройка первой не означает наличие второй.

Обычная silent-установка и WinGet не запускают приложение автоматически. Если для обновления нужен перезапуск через установщик, он разрешается только отдельным явным параметром из контролируемого процесса обновления и проверяется отдельно.

## Приёмка

1. TDD для настроек согласия и отсутствия сети до разрешения, отзыва разрешения и ручной проверки.
2. Настоящая проверка подписи: корректный пакет, изменённые байты, другой ключ, неподписанный или повреждённый feed.
3. Ошибки сети, прерванная загрузка, повторная проверка, текущая/старая/новая версия.
4. Реальные WPF-состояния с синтетическим профилем, сохранение согласий и доступная отмена.
5. Установка и перезапуск с сохранением профиля/очереди только на временном GitHub Windows runner или отдельно разрешённой изолированной системе. Рабочий профиль и экземпляр пользователя не используются как фикстуры.
6. Полная регрессия клиента и упаковки, независимое ревью, PR в `develop` с одобрением FForq. Прямой push и обход защиты запрещены.

Публичный Release создаётся из проверенного `master` отдельным тегом владельца. Регистрация в WinGet и изменение публичного сайта не входят в эту доработку.
