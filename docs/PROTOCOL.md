# Клиентский протокол, версия 1

Публичное описание транспортного контракта клиента. Серверная реализация в этот репозиторий не входит. Для проверки совместимости предназначены синтетические тесты `TjClient.Tests`.

## Безопасность и идентичность

- Базовый адрес - HTTPS origin без пользовательских данных, query, fragment и подпути. Проверяются цепочка сертификата и имя узла, редиректы не выполняются.
- Авторизация: `Authorization: Bearer <source-key>`. Дополнительный заголовок: `X-Requested-With: TJCloudClient`.
- Источник определяется ключом, а не произвольным `source_id` в запросе отправки. Сервер обязан проверять принадлежность передачи при каждом обращении.
- Размеры и смещения - целые байты. Файл идентифицируется относительным путём, размером и SHA-256. Один путь с изменившимся содержимым является конфликтом, а не заменой уже зарегистрированного файла.
- Файл публикуется источником под окончательным `.log` только после завершения записи. Клиент не предназначен для чтения активного журнала.

## Проверка подключения

`GET /api/collector/v1/status`

Ответ содержит `protocol_version`, `source_id`, `source_name`, `chunk_bytes`, `max_file_bytes`. Клиент поддерживает протокол 1, положительный `source_id` и блоки не больше 4 МиБ. Вызов не передаёт содержимое журналов.

## Регистрация

`POST /api/collector/v1/uploads`

```json
{
  "relative_path": "rphost_100/26010100.log",
  "size_bytes": 21,
  "sha256": "<64 lowercase hexadecimal characters>"
}
```

Пример является схемой, а не готовым запросом: размер и SHA-256 должны вычисляться из настоящего отправляемого файла.

Путь использует `/`, не содержит абсолютного корня, `.`/`..`, пустых сегментов, обратных слешей, двоеточий или управляющих символов. Поддерживаемые имена процессов и файлов проверяются сканером и должны независимо проверяться сервером.

Повтор одинаковой регистрации возвращает ту же передачу и подтверждённое смещение. Конфликт идентичности - HTTP 409.

## Объект передачи

Ответы регистрации, чтения состояния, блока и завершения используют поля:

- `upload_id`: UUID;
- `relative_path`, `size_bytes`, `received_bytes`;
- `status`: `uploading`, `queued`, `importing`, `imported`, `failed` или `expired`;
- `job_id`: целое число или null;
- `error`: строка или null.

`GET /api/collector/v1/uploads/{upload_id}` возвращает состояние передачи. Чужой ID не должен раскрывать сведения о передаче.

## Передача блока

`PUT /api/collector/v1/uploads/{upload_id}/chunk?offset=<confirmed-offset>`

- Тело - gzip одного блока.
- `Content-Type: application/octet-stream`.
- `Content-Encoding: gzip`.
- `X-Chunk-SHA256` - SHA-256 несжатого блока.
- Несжатый размер не превышает объявленный `chunk_bytes`.

В ответе сервер подтверждает `received_bytes`. Клиент не продвигает локальное смещение без подтверждения. После обрыва соединения сначала сверяется состояние сервера; повтор диапазона допустим только для тех же байтов.

## Завершение и импорт

`POST /api/collector/v1/uploads/{upload_id}/complete`, без тела.

Сервер проверяет размер и SHA-256 всего файла и идемпотентно связывает его с обработкой. Повтор завершения не должен создавать повторный импорт.

`queued` означает получение сервером, не завершение анализа. Клиент отдельно опрашивает состояние. Уже принятый файл автоматически не отправляется заново ради повторного импорта. Потерянное подтверждение завершения восстанавливается по `upload_id`, в том числе при исчезнувшем исходном файле.

## Ошибки и ограничения

Неверный/отозванный ключ - 401, приостановленный источник - 403, конфликт - 409, превышение размера - 413. Сетевые временные ошибки используют сохранённый backoff. Ошибка сертификата не считается обычной временной сетевой ошибкой. Отмена пользователем не продвигает неподтверждённое смещение.

Клиент ограничивает файл 2 ГиБ и дополнительно соблюдает меньший лимит сервера. Очередь/сканирование ограничены 10000 файлами, глубина обхода - 8. Превышающий лимит файл сохраняется с видимой ошибкой и не должен блокировать остальные файлы.

Ключи, содержимое журналов и внутренние серверные пути не должны возвращаться в ошибках. Конкретные эксплуатационные квоты сервера не являются частью этого клиентского контракта.
